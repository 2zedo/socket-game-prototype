# 해킹 액션 모드 방향

## 목적

이 문서는 유이가 노트북으로 수행하는 의뢰 작업을 장기적으로 별도 `3/4 top-down` 액션 해킹 모드로 확장할 때의 고수준 방향을 정리한다.

이번 문서는 구현 지시가 아니다. 현재 DAY 1 MVP의 방 화면, 전력, Phone, Result, Test Mode 로직은 유지하며, 해킹 액션 모드는 장기 방향으로만 다룬다.

## 핵심 구분

`CONCENT / 전력 부족의 시대`는 현실 방 파트와 해킹 파트를 분리해서 생각한다.

현실 파트는 유이의 방이다. 제한된 전력 안에서 장치를 연결하고, Phone으로 상태를 확인하고, 노트북과 통신 장치를 켜며, 하루 결과를 생존 기록으로 남기는 생활 관리 공간이다.

해킹 파트는 노트북을 통해 진입하는 별도 `3/4 top-down` 액션 모드다. 이 공간은 현실의 방이 아니라 `THE GRID` 내부의 보안망, 폐쇄망, 검열 시스템, 감시 프로세스를 시각화한 사이버 공간이다.

두 파트는 같은 세계관에 속하지만, 플레이 감각과 시각 언어는 명확히 달라야 한다.

## 해킹 액션 모드의 역할

유이는 재미로 모험하는 것이 아니다.

유이는 생존과 돈벌이를 위해 위험한 비공식 정보 의뢰를 수행한다. 의뢰는 삭제된 로그, 검열된 자료, 외부 신호, 감시망 흔적처럼 `THE GRID`가 숨기거나 관리하는 정보와 연결된다.

해킹 액션 모드는 이 의뢰 작업을 플레이 가능한 별도 모드로 표현한다.

- 노트북을 통해 해킹 공간에 진입한다.
- 보안 프로그램과 장애물을 돌파한다.
- 목표 노드를 처리한다.
- 추적이나 경보를 피해 연결을 종료하거나 탈출한다.
- 성공 또는 실패 결과를 현실 방 루프로 되돌린다.

## 공간 방향

현실 방은 어둡고 생활감 있는 전력 관리 공간이다. 해킹 공간은 더 추상적이고, 디지털적이고, 적대적인 공간이어야 한다.

해킹 공간은 판타지 던전처럼 보이면 안 된다. 벽, 함정, 적, 문, 보상 상자를 그대로 사이버 장식으로 바꾸는 방식보다, `THE GRID`의 보안 시스템 내부를 통과한다는 느낌이 중요하다.

사용 가능한 적과 장애물 후보는 아래와 같다.

- 보안 프로그램
- 방화벽 노드
- 추적 드론
- 스캔 빔
- 경보 노드
- 감시 프로세스
- 움직이는 전기 장벽
- 손상되거나 붕괴되는 데이터 타일

## 플레이어 행동

해킹 액션에서 플레이어는 아래 행동을 수행할 수 있다.

- 이동
- 공격 또는 도구 사용
- 회피
- 짧은 기동성 행동
- 노드 상호작용
- 목표 달성 후 탈출 또는 연결 종료

점프는 플랫폼 게임식 점프가 아니다. 내려다보는 액션 시점에서 함정 회피, 위험 구역 통과, 짧은 기동성 부여를 위한 행동으로 검토한다. 실제 구현 여부와 조작 방식은 prototype 단계에서 확인한다.

## 보상과 실패

미션 성공 시 유이는 아래 보상을 얻을 수 있다.

- Grid Credit
- 정보 조각
- 스토리 플래그
- Result 기록에 남는 의뢰 성과

미션 실패 시 아래 손실이 발생할 수 있다.

- 시간 손실
- 전력 손실
- 보상 감소
- 정보 획득 실패
- 다음 의뢰 조건 악화

처음부터 복잡한 경제나 스킬트리를 만들지 않는다. 핵심은 해킹 액션 결과가 현실 방의 전력, 시간, 정보, 생존 기록과 연결되는지 검증하는 것이다.

## 시각 방향

첨부 이미지는 reference only로 취급한다. 이미지는 아래 요소를 참고하기 위한 분위기 자료다.

- 탑뷰 액션 전투감
- 사이버 공간 느낌
- 보안 시스템 내부를 통과하는 느낌
- 함정과 경보 장치
- 디지털 노이즈, 스캔 라인, 보안 UI 분위기
- 완전 정수리뷰보다 캐릭터 / 적 / 장애물 앞면이 조금 보이는 `3/4 top-down cyber action view`

첨부 이미지에서 아래 요소를 그대로 가져오지 않는다.

- 이미지의 맵 구조
- 적 디자인
- UI 배치
- 특정 게임의 전투 방식
- 캐릭터 디자인
- 색상 팔레트 전체

최종 방향은 `CONCENT`와 `THE GRID`의 세계관에 맞게 정리한다. 해킹 공간은 화려한 전투장보다, 유이가 하층 정보 노동자로서 위험한 보안망에 접속한다는 긴장감을 우선한다.

## 현재 구현

- 노트북은 현재 방 안 상호작용 오브젝트다.
- 해킹 액션 모드는 아직 구현되어 있지 않다.
- 전력, Phone, Result, `02:00` 종료, Test Mode는 기존 DAY 1 MVP에 구현되어 있다.
- 현재 노트북 사용은 별도 액션 미션으로 이어지지 않는다.
- 현재 `HackingActionPrototype`은 조작 / 상태 흐름 검증용이며, 장기 목표 시점 자체는 `res://scenes/prototypes/HackingPerspectiveBlockout.tscn`에서 따로 검증한다.
- 해킹 미션 데이터는 장기적으로 `HackingMissionDefinition` Resource로 관리한다.
- 해킹 arena 시각은 판타지 던전 tile이 아니라 cyber / network arena tile을 우선하며, tile 기준은 `docs/HACK_ARENA_TILES_ATLAS_REGION_MAPPING.md`에서 관리한다.

## 장기 방향

- 노트북에서 별도 `3/4 top-down` 액션 해킹 미션으로 진입한다.
- 노트북의 미션 선택은 향후 `HackingMissionDefinition` Resource 목록을 읽는 방향으로 검토한다.
- 해킹 성공과 실패는 Grid Credit, 정보 플래그, Result 기록, 전력 또는 시간 손실에 연결한다.
- 현실 방 파트와 해킹 파트는 시각적으로 구분하되, 전력과 의뢰 결과를 통해 하나의 하루 루프로 이어지게 한다.
- 첫 구현은 작은 해킹 미션 1개로 시작한다.

## 이번 작업의 범위

- 현재 구현 = 방 안 노트북 상호작용 오브젝트
- 장기 방향 = 별도 `3/4 top-down` 액션 해킹 모드 검토
- 이번 작업 = 문서화 / Resource 설계
- 이번 작업에서 구현하지 않음 = scene 변경, mission `.tres` 생성, Laptop 연결, Result / Story / Grid Credit 연결, 에셋 추가, 해킹 액션 prototype scene 생성
