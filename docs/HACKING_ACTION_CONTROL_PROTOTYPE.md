# 해킹 액션 Prototype 최소 조작 정의

## 목적

이 문서는 노트북에서 진입할 장기 해킹 액션 모드의 첫 prototype을 만들기 전에, 최소 조작과 미션 구조를 정리한다.

이번 문서는 구현 지시가 아니다. 현재 DAY 1 MVP의 방 화면, 전력, Phone, Result, Test Mode, 노트북 상호작용은 변경하지 않는다. 해킹 액션은 아직 구현하지 않으며, 이 문서는 첫 prototype에서 무엇을 넣고 무엇을 빼둘지 정하기 위한 기준이다.

## 첫 Prototype의 핵심 방향

첫 해킹 액션 prototype은 아래 요소만 검증한다.

```text
이동
공격 / 해킹 샷
점프
구르기 회피
노드 상호작용
피격 / 실패
탈출
```

복잡한 성장 요소, 복수 무기, 스킬, 경제, 여러 미션, 스토리 분기는 첫 prototype에 넣지 않는다. 목표는 해킹 액션의 기본 손맛과 현실 방 루프 연결 가능성을 작게 확인하는 것이다.

Arena tile mapping remains separate visual / data work. The control prototype tests movement, shot, roll, hop, objective, and failure feel without requiring `hack_arena_tiles_atlas.png`.

## 조작 후보

아래 입력은 prototype 후보이며, 실제 구현 시 기존 프로젝트 입력과 충돌하면 조정할 수 있다.

| 행동 | 추천 입력 | 역할 |
| --- | --- | --- |
| 이동 | WASD / 방향키 | 탑뷰 이동 |
| 공격 / 해킹 샷 | 마우스 좌클릭 또는 J | 보안 프로그램 공격, 노드 약화 |
| 점프 | Space | 함정 넘기, 위험 타일 회피 |
| 구르기 회피 | Shift 또는 K | 짧은 회피 기동 |
| 노드 상호작용 | E | 목표 노드 접속, 데이터 회수 |
| 취소 / 미션 중단 | ESC | prototype 단계의 일시 중지 또는 테스트 종료 후보 |

첫 구현에서는 입력 수를 늘리지 않는다. 이동, 기본 공격, 점프, 회피, 상호작용, 중단만으로 미션이 성립하는지 먼저 확인한다.

## 점프 정의

점프는 플랫폼 게임식 점프가 아니다.

해킹 액션 prototype에서 점프는 함정 넘기 용도의 기동 행동이다. 플레이어가 높이 올라가거나 맵 지형 위아래를 오가는 행동이 아니라, 탑뷰 공간에서 위험 구간을 타이밍으로 넘는 행동으로 취급한다.

점프로 넘을 수 있는 것:

- 낮은 데이터 장벽
- 스캔 라인
- 전기 타일
- 붕괴 직전 타일
- 짧은 위험 구간

점프로 넘을 수 없는 것:

- 벽
- 보안문
- 큰 장애물
- 맵 경계
- 목표 노드 자체

점프는 전투 공격 수단이 아니다. 적을 밟거나 피해를 주는 행동이 아니라, 위험 타일과 스캔을 통과하기 위한 기동 선택지다.

## 구르기 회피 정의

구르기 회피는 대시라기보다 짧은 회피 동작이다.

- 짧은 거리만 이동한다.
- 보안 프로그램의 탄, 스캔, 근접 공격을 피하는 용도다.
- 벽이나 큰 장애물을 통과하지 않는다.
- 함정을 완전히 무시하는 만능 회피가 아니다.
- 점프와 역할을 분리한다.

점프와 구르기 회피의 차이는 아래처럼 잡는다.

```text
점프:
- 함정 / 위험 타일을 넘는 행동

구르기 회피:
- 적 공격이나 스캔을 피하는 짧은 회피 행동
```

첫 prototype에서는 두 행동이 모두 필요하지 않다고 판단되면 하나를 임시 비활성화할 수 있다. 단, 문서 기준에서는 역할을 분리해 둔다.

## 공격 / 해킹 샷 정의

공격은 일반 총격보다 노이즈 펄스 / 해킹 샷 계열 행동으로 취급한다.

- 공격은 보안 프로그램을 파괴하거나 약화하는 기본 행동이다.
- 코드나 내부 이름은 `attack`이어도 되지만, 기획상으로는 해킹 샷 또는 노이즈 펄스 계열로 본다.
- 첫 prototype에서는 단순 발사체 하나면 충분하다.
- 발사체는 목표 방향으로 날아가고, 보안 프로그램 또는 약화 가능한 노드에 닿으면 효과를 준다.
- 탄약, 무기 교체, 속성, 스킬, 장비 성장은 첫 prototype 범위에서 제외한다.

공격은 현실 방의 폭력 액션이 아니라, 유이가 보안망 안에서 디지털 방어 시스템을 교란하는 행동으로 표현한다.

## 첫 Prototype 미션 구조

첫 미션은 작고 명확해야 한다.

```text
목표:
손상된 로그 노드 1개 회수

맵:
작은 사이버 공간 방 1개 또는 짧은 복도형 맵

방해 요소:
보안 프로그램 2~3개
스캔 라인 함정 1종
전기 타일 또는 위험 구간 1종

성공 조건:
목표 노드에 E로 접속
데이터 회수 후 탈출 지점으로 이동

실패 조건:
HP 0
또는 trace 100%
또는 prototype 단계에서는 단순히 체력 0만 실패로 시작 가능

보상:
정보 조각 1개
소량의 Grid Credit 후보
Result 기록에 남길 수 있는 짧은 성공 문장 후보
```

Grid Credit은 아직 본 구현 경제가 아니다. 첫 prototype에서는 문서상 후보로만 두고, 실제 경제 시스템을 구현하지 않는다.

## 피격 / 실패 기준

첫 prototype의 실패 기준은 단순해야 한다.

첫 prototype 필수:

- HP 기반 실패
- 플레이어 HP 또는 안정도 3칸 후보
- 보안 프로그램 공격에 맞으면 1 감소
- HP가 0이 되면 미션 실패

나중 후보:

- trace 100%
- 경보 단계 상승
- 시간 제한
- 위험 타일 접촉 시 trace 증가
- 실패 시 보상 감소 또는 정보 손실

위험 타일은 첫 prototype에서 HP를 깎는 방식으로 시작해도 된다. trace 시스템은 해킹 모드 분위기에 어울리지만, 처음부터 필수로 넣지 않는다.

## 탈출 정의

첫 prototype은 목표 노드를 처리하고 바로 끝나는 것보다, 탈출까지 포함하는 편이 해킹 의뢰 느낌을 더 잘 살린다.

- 목표 노드를 처리하면 탈출 지점이 열린다.
- 탈출 지점으로 이동하면 미션 성공이다.
- 연결 종료 연출은 나중에 추가한다.
- 첫 prototype에서는 간단한 success state로 충분하다.

탈출은 보상 상자나 스테이지 클리어 화면이 아니라, 위험한 보안망에서 데이터를 들고 빠져나오는 행위로 느껴져야 한다.

## 현실 방 루프와의 연결

이번 문서에서는 연결 방향만 정리하고 구현하지 않는다.

- 노트북을 켜고 있는 동안 해킹 미션이 진행된다.
- 현실 방에서는 노트북 active 시간이 전력을 소비한다.
- 해킹 미션 성공 / 실패는 Result 기록에 반영될 수 있다.
- 통신 장치, 신호 증폭기, NODE-17 같은 현실 장비가 나중에 미션 조건에 영향을 줄 수 있다.
- Phone 배터리나 의뢰 메시지는 미션 선택과 결과 확인에 영향을 줄 수 있다.
- 첫 prototype에서는 이 연결을 모두 구현하지 말고, 미션 하나가 독립적으로 작동하는지 먼저 확인한다.

## 첫 Prototype에서 제외할 것

첫 prototype에는 아래 항목을 넣지 않는다.

- Grid Credit 경제 본 구현
- 복수 미션 목록
- 스킬트리
- 무기 교체
- 장비 성장
- 속성 공격
- 복잡한 경보 단계
- DAY 2+ 스토리 분기
- 현실 방 장비에 따른 세부 난이도 변화
- 저장 / 로드

## 현재 구현과의 구분

- 현재 구현: 노트북은 방 안 상호작용 오브젝트다.
- 현재 구현: 전력, Phone, Result, `02:00` 종료, Test Mode는 DAY 1 MVP에 있다.
- 현재 미구현: 해킹 액션 모드, Grid Credit 경제, 의뢰 목록 UI, 해킹 미션 결과 정산.
- 장기 방향: 노트북에서 작은 해킹 액션 prototype 미션으로 진입하고, 이후 현실 방 Result와 정보 플래그로 연결한다.
- 이번 작업: 문서화.
- 이번 작업에서 구현하지 않음: 코드 변경, scene 변경, Resource 변경, 에셋 추가, 해킹 액션 prototype scene 생성.

## 다음 설계에서 확인할 것

- 해킹 액션 prototype의 카메라 크기와 맵 한 화면 기준
- HP UI와 trace 후보를 어떻게 구분할지
- 해킹 샷의 사거리와 발사 방향 처리
- 점프와 구르기 회피 중 첫 prototype에 둘 다 넣을지 여부
- 방 노트북 상호작용에서 prototype scene으로 들어가는 UX 경계
