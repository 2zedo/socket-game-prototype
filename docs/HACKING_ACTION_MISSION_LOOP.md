# 해킹 액션 미션 루프

## 목적

이 문서는 노트북을 통해 진입하는 장기 해킹 액션 모드의 미션 흐름을 정리한다.

현재 DAY 1 MVP에는 해킹 액션 모드가 구현되어 있지 않다. 이 문서는 이후 작은 prototype 미션을 설계할 때 현실 방 루프와 어떻게 연결할지 정리하기 위한 기준이다.

## 기본 진입 흐름

해킹 액션 미션은 현실 방에서 시작해 현실 방으로 돌아온다.

```text
방에서 노트북 사용
→ 의뢰 확인
→ 해킹 미션 진입
→ 보안 공간 탐색
→ 적/함정 회피 또는 파괴
→ 목표 노드 처리
→ 탈출 또는 연결 종료
→ 방으로 복귀
→ 보상/정보/전력/시간 정산
```

이 흐름의 핵심은 해킹 액션이 별도 게임처럼 고립되지 않는 것이다. 노트북을 켜는 현실 선택, 전력 소비, 의뢰 보상, Result 기록이 하나의 하루 루프로 이어져야 한다.

## 미션 목표 예시

초기 미션은 작고 명확해야 한다. 처음부터 여러 분기나 복잡한 목표를 넣지 않는다.

미션 목표 후보는 아래와 같다.

- 손상된 로그 복원
- 삭제된 아카이브 회수
- 감시 노드 비활성화
- 외부 신호 경로 추적
- 가짜 신호 심기
- 보안 레이어 돌파 후 탈출

각 미션은 목표 노드 하나와 탈출 조건 하나를 중심으로 시작한다. 스토리 플래그나 정보 조각은 미션 성공 후 현실 방 Result에 연결한다.

## 위험 요소 예시

해킹 공간의 위험 요소는 인간 적이 아니라 보안 시스템이다.

- 보안 프로그램
- 추적 드론
- 스캔 빔
- 경보 노드
- 움직이는 전기 장벽
- 붕괴되는 데이터 타일
- 밟으면 추적률이 오르는 함정

위험 요소는 플레이어에게 단순 전투보다 판단을 요구해야 한다. 공격해야 하는 대상, 피해야 하는 감시, 빠르게 지나가야 하는 위험 구역이 섞이면 좋다.

## 보상 구조

해킹 의뢰는 위험과 보상이 다른 선택지로 확장할 수 있다.

쉬운 의뢰:

- 보상 적음
- 위험 낮음
- 기본 Grid Credit 획득

어려운 의뢰:

- 보상 큼
- 정보 단서 획득 가능
- 실패 시 손실 큼

초기 구현에서는 쉬운 의뢰 하나만 만들어도 충분하다. 목표는 경제 시스템 전체가 아니라, 해킹 미션 결과가 현실 방 루프와 연결되는지 확인하는 것이다.

## 현실 파트와의 연결

해킹 미션은 현실 방의 전력 관리와 연결되어야 한다.

- 노트북을 켜고 있는 시간은 전력을 소비한다.
- 통신 장치나 신호 증폭기 같은 현실 장치가 해킹 미션 조건에 영향을 줄 수 있다.
- Phone 배터리나 의뢰 메시지는 미션 선택과 결과 확인에 영향을 줄 수 있다.
- 미션 결과는 Result의 생존 기록에 남을 수 있다.
- 실패는 시간, 전력, 보상, 정보 획득에 손해를 줄 수 있다.

현실 방에서 어떤 장치를 켰는지가 해킹 미션에 작게라도 영향을 주면, 전력 배분과 의뢰 선택이 같은 루프 안에서 의미를 갖는다.

## 초기 구현 방향

첫 구현은 미션 1개만 목표로 한다.

- 작은 맵 하나
- 목표 노드 하나
- 보안 적 또는 함정 1~2종
- 명확한 성공 조건
- 명확한 실패 또는 손실 조건
- 방으로 돌아온 뒤 Result에 기록되는 짧은 결과

처음부터 복잡한 경제, 스킬트리, 여러 미션 분기, 다양한 보상 테이블을 만들지 않는다. 핵심은 "노트북으로 들어간 별도 탑뷰 액션 의뢰가 현실 방 루프와 연결되는지"를 검증하는 것이다.

## 미션 데이터 관리 후보

Laptop mission selection은 장기적으로 `HackingMissionDefinition` Resource 목록을 읽는 방향으로 검토한다. 이 Resource는 mission key, 표시명, 유형, 목표, 요구 / 추천 장치, story flag 후보, 보상 후보, Result 문구 후보를 관리한다.

현재는 Resource class만 준비되어 있으며, 실제 mission `.tres`, Laptop UI, `HackingActionPrototype` 진입, Grid Credit, Result, Story flag 연결은 아직 구현하지 않는다.

Future hacking missions may use `map_scene_path` plus `hack_arena_tiles_atlas.png` / TileSet mapping to construct mission spaces. This is not wired yet.

Future hacking missions may select enemy visuals and behavior hints from `hack_enemies_atlas.png` mapping data. This is not wired yet.

## 현재 구현

- 노트북은 방 안 상호작용 오브젝트다.
- 해킹 액션 모드는 아직 없다.
- 전력, Phone, Result, Test Mode는 기존 DAY 1 MVP에 있다.
- 현재 Result는 하루 생존 기록을 표시하지만, 해킹 미션 보상이나 Grid Credit 정산은 아직 없다.

## 장기 방향

- 노트북에서 별도 탑뷰 액션 해킹 미션으로 진입한다.
- 해킹 성공과 실패가 Grid Credit, 정보 플래그, Result 기록, 전력 또는 시간 손실에 연결된다.
- 현실 방의 장치 선택이 해킹 미션 조건이나 난이도에 영향을 줄 수 있다.
- 첫 구현은 작은 미션 하나로 시작하고, 이후 의뢰 종류와 위험 요소를 확장한다.

## 이번 작업의 범위

- 현재 구현 = 방 안 노트북 상호작용
- 장기 방향 = 별도 탑뷰 액션 해킹 미션
- 이번 작업 = 문서화
- 이번 작업에서 구현하지 않음 = 코드 변경, scene 변경, Resource 변경, 에셋 추가, 해킹 액션 prototype scene 생성
