# CONCENT Room / Power / Hacking Design Direction

이 문서는 `CONCENT / 전력 부족의 시대`의 메인방, 전력 장비, 해킹 액션, 해킹 방어 방향을 고정하기 위한 디자인 기준 문서다. 최종 아트 사양서나 구현 작업 지시서가 아니며, 최근 생성한 회의용 reference board 이미지를 그대로 따라 만들기 위한 문서도 아니다.

회의용 이미지는 메인방 / 전력 장비 / 해킹 액션 / 해킹 방어의 방향을 논의하기 위한 reference board로만 본다. 일부 메인방 디자인과 해킹 액션 디자인은 실제 의도와 어긋난 부분이 있으므로, 이후 구현 판단에서는 이 문서의 텍스트 결정사항을 우선한다.

## 1. 문서 목적

- 메인방, 전력 장비, 해킹 모드의 디자인 방향을 한 곳에 고정한다.
- Godot 구현 시 어떤 UI / scene / resource 판단을 해야 하는지 참고 기준을 제공한다.
- 회의용 이미지를 최종 아트나 확정 레이아웃으로 오해하지 않게 한다.
- 기존 Main / DAY1을 즉시 교체하지 않고, QuarterviewMain 후보와 sandbox 단계를 통해 검증한다.

이 문서에서 정리하는 내용은 현재 production 연결이 아니다. Phone UI, OutletMode, Result, SurvivalState, Hacking, Grid Credit, story flag, save/load 연결은 별도 승인 작업에서 진행한다.

## 2. 메인방 디자인 방향

메인방은 WASD 자유 이동 중심이 아니라 마우스 클릭 중심으로 설계한다.

기본 흐름:

```text
오브젝트 클릭
-> 유이가 해당 위치로 이동
-> 사용하기 / 설명(살펴보기) / 취소 패널 표시
-> 선택에 따라 방 / 책상 클로즈업 / 전력 장비 / 기타 UI로 진입
```

WASD는 메인 조작이 아니라 보조 조작 또는 PC 편의 / debug 이동 정도로 둔다. 플레이어가 방을 자유롭게 돌아다니는 감각보다, 작은 방 안에서 오브젝트를 고르고 접근하는 point-and-click 어드벤처 감각을 우선한다.

방의 핵심 인상:

- 작은 하층민 1인실 + 해커 작업실
- 너무 넓은 연구실처럼 보이면 안 됨
- 생활 공간과 작업 공간이 자연스럽게 섞임
- 책상은 해킹 / 분석 / 의뢰 확인의 중심 오브젝트
- 오른쪽 구석에는 전력 장비 구역이 밀도 있게 들어감
- 중앙의 작은 탁상은 제거 후보

구현 판단:

- `QuarterviewMain`의 임시 배경은 방향 확인용으로 사용하되, interaction / collision / prompt는 별도 invisible data로 관리한다.
- 방 visual이 먼저 좋아 보이더라도, 실제 조작은 object key / interaction area / room contract 기준으로 분리한다.
- 방이 넓어 보이면 오브젝트를 더 크게 흩뿌리기보다, camera framing과 방 내부 밀도를 조정한다.

## 3. 책상 클로즈업 방향

책상은 단순한 `laptop` 클릭 UI가 아니라, 해커로서 실제 장비를 다루는 느낌을 주는 중심 화면이다.

권장 흐름:

```text
책상 오브젝트 클릭
-> 유이가 책상으로 이동하거나 앉는 짧은 연출
-> 책상 클로즈업 화면 전환
-> 노트북 / 통신 장비 / 스피커 / NODE-17 / 신호 증폭기 등 선택
-> 해킹, 분석, 의뢰 확인, 신호 확인 등으로 진입
```

책상 위 주요 장비:

- 노트북
- 통신 장비
- 스피커 / 오디오 분석 장비
- NODE-17
- 신호 증폭기
- 기타 해킹 보조 장치

책상 클로즈업의 목적은 “메뉴 UI”가 아니라 “장비를 실제로 사용하는 화면”이다. 따라서 바로 추상 메뉴로 점프하기보다, 장비 표면과 배치, 작은 LED, 케이블, 화면, 소리 장비가 읽히는 방향이 좋다.

## 4. 전력 장비 방향

기존 멀티탭은 장기적으로 오른쪽 구석의 compact 데이터센터 랙 / Molex / 모듈형 전력 보드 느낌으로 재설계한다. 너무 거대한 서버랙은 금지한다. 방 한쪽에 억지로 들여놓은 작고 밀도 높은 전력 장비가 좋다.

전력 보드 형태 참고:

- 바둑판 배치
- 벌집형 배치
- 메이플 유니온 같은 모양 맞추기 배치

단, 징그러운 벌집 느낌은 피하고 기계적인 슬롯 / 모듈 보드 느낌으로 간다.

모듈 후보:

- 콘센트 모듈
- RAM 형태 모듈
- 해킹 보조 모듈
- 냉각 모듈
- 신호 모듈
- 드론 / 무기 모듈

퍼즐 의미를 위해 모듈은 서로 다른 모양을 가져야 한다. 단순히 같은 사각형을 많이 꽂는 구조면 배치 퍼즐이 약해진다.

초기 규칙 방향:

- 작고 단순한 모듈은 전력 소모가 큼
- 크고 이상한 모양의 모듈은 전력 효율이 좋음
- 플레이어는 칸 부족, 전력 부족, 발열 위험 사이에서 선택함
- 초반 관리 축은 `전력 + 발열 + 보너스 효과`
- 습도와 안정도는 초반 제외
- 전력 / 발열 관리 실패는 즉시 게임오버가 아니라 효율 저하, 위험 증가, 경고, 성능 저하로 처리

해킹 연계:

- 전력 장비 세팅은 해킹 모드의 무기 증가, 업그레이드, 보조 드론, 스텔스 보정과 연결된다.
- 기본 공격은 자동 단발 발사체로 시작한다.
- 이후 모듈에 따라 발사체 수, 방향, 쿨다운, 보조 드론, 스텔스 보정, 센서 범위가 바뀔 수 있다.

## 5. 유이의 방 디자인 / 성격 반영

유이는 THE GRID 바깥 자유를 동경한다. “새 / 날개”는 직접적인 장식 요소를 넣자는 뜻이 아니라, 자유를 갈망한다는 비유로 이해한다.

방 안에는 바깥 세계와 바다를 동경하는 오브젝트가 한눈에 보이면 좋다. 단, 방 전체를 해변방처럼 만들면 안 된다. 어둡고 좁은 인공 도시의 방 안에, 도달하기 어려운 바깥 세계를 바라보는 조그마한 흔적이 있는 방향이다.

가능한 오브젝트:

- 낡은 바다 포스터
- 바다 화면보호기
- 해변 광고 전단
- 파란 조명
- 물결 이미지
- 인공 조개 장식

바다는 인공 도시에서 쉽게 갈 수 없는 상상 속 자유의 상징이다. 이 모티프는 과하게 꾸미기보다, 방의 어둡고 좁은 분위기 안에서 작은 위로처럼 보이게 둔다.

## 6. 음식 / 허기 디자인

허기 시스템은 유지한다.

기본 방향:

- 허기가 낮으면 상태이상 또는 디버프
- 허기가 높거나 잘 관리되면 버프
- 초반에는 음식별 복잡한 효과보다 허기 관리 중심으로 단순하게 둔다

음식 세계관:

- 가공육
- 인공육
- 배양육
- 채소
- 합성 식품

해산물은 매우 사치스러운 음식이며, 바깥 세계 / 바다의 상징으로도 쓸 수 있다. 해산물은 단순 회복 아이템보다 “바다에 대한 동경”을 건드리는 이벤트나 보상으로 쓰면 좋다.

## 7. 해킹 모드 전체 구조

해킹 모드는 크게 두 종류만 둔다.

| 분류 | 핵심 |
| --- | --- |
| 액션 침투 | 침투, 데이터 탈취, 탈출 |
| 방어 | 침입 패킷 / 바이러스 / 시스템 위협을 상대로 일정 시간 생존 |

전투형과 스텔스형은 완전히 별도 모드가 아니다. 같은 액션 침투 모드 안에서 장비 세팅과 플레이 방식에 따라 갈리는 스타일이다.

해킹은 단순 코딩 퍼즐이 아니라, 상대 시스템에 침투해 데이터를 탈취하는 SF 액션 게임으로 표현한다. 퍼즐 요소는 스텔스 / 우회 / 보안 장치 해킹에 섞는다.

## 8. 액션 침투 모드

목표:

```text
침투 -> 데이터 탈취 -> 탈출
```

시점과 카메라:

- 대각선 아이소메트릭이 아님
- 정면성이 있는 45도 상단 시점
- 던전앤파이터처럼 횡 이동 감각이 있지만, X / Y / Z 축을 모두 쓰는 2.5D 침투 액션
- 기존 보드 이미지보다 카메라를 더 가까이 두어 긴장감 강화
- 마우스 포인터 방향으로 카메라가 약간 따라 움직여 먼 거리도 일부 확인 가능
- 오브젝트 위 / 뒤에 있는 적과 플레이어는 가려져 보이지 않아야 함
- 시야, 가림, 엄폐, 우회 루트가 중요함

### 전투형

전투형은 시원한 SF 액션과 경로 선택의 긴장감을 결합한다.

- 정찰형 바퀴 달린 드론
- 광선검 / SF 액션 무기
- 업그레이드 시 원거리 보조 공격 드론
- 구르기, 대시, 시원한 돌파
- 적을 섬멸하고 데이터를 탈취한 뒤 탈출
- 막힌 문이나 지름길은 무조건 부수지 않고 우회해야 함

핵심은 “전투가 시원하지만, 무작정 직선 돌파만으로 끝나지 않는 것”이다.

### 스텔스형

스텔스형은 조용한 침투, 퍼즐, 우회, 선택적 제거가 중심이다.

- 은신, 숨기
- 적 시야 회피
- 막힌 문이나 보안 장치 해킹
- 신호 조정 퍼즐
- 노드 연결 퍼즐
- 가까이 접근하면 빔 형태의 교살용 와이어 / 데이터 와이어로 조용히 제거
- 데이터 탈취 후 흔적을 최소화하고 탈출

스텔스형은 적을 다 없애는 모드가 아니다. 들키지 않고 필요한 것만 하고 빠져나오는 긴장감이 핵심이다.

## 9. 해킹 방어 모드

해킹 방어는 뱀파이어 서바이벌 같은 생존 이벤트형으로 둔다. 중앙 코어를 가만히 지키는 방식은 재미가 약하므로 피한다.

방향:

- 플레이어가 직접 움직이며 피하고 사냥한다.
- 플레이어 자신이 백신 / 코어 같은 존재가 되어 움직이는 편이 좋다.
- 적은 랜덤하게 달려들거나 지나간다.
- 플레이어는 회피, 사냥, 위치 조정으로 일정 시간 버틴다.
- 기본 공격은 자동 단발형 발사체.
- 전력 장비 모듈 세팅으로 무기 수, 공격 방식, 보조 드론, 발사체 효과 등이 증가한다.
- 방어 모드는 매일 발생하지 않고 이벤트형으로 사용한다.

비주얼:

- 바이러스
- 백신
- 시스템 방어
- 침입 패킷
- 방화벽 / 격리 구역

방어 모드는 단순 뱀서 복붙처럼 보이면 안 된다. `CONCENT`의 해킹 세계관 안에서 “시스템에 밀려드는 침입을 직접 움직이며 막는 이벤트”로 보여야 한다.

## 10. 대안점 / 주의점

### 대안점

- 메인방 조작은 마우스 중심이지만, WASD 보조 이동은 남길 수 있다.
- 전력 보드는 초반에 모듈 수를 제한하고, 후반에 복잡한 모양과 보정 기능을 추가한다.
- 액션 침투는 하나의 모드로 만들고, 장비 세팅에 따라 전투형 / 스텔스형이 갈리게 한다.
- 방어는 처음에는 짧은 이벤트형으로 시작하고, 반응이 좋으면 독립 모드로 확장한다.

### 주의점

- 메인방이 너무 넓은 연구실처럼 보이면 안 된다.
- 전력 보드는 복잡해야 의미가 있지만, UI 가독성은 확보해야 한다.
- 전력 / 발열 실패는 즉시 게임오버보다 경고 / 효율저하 / 위험증가가 좋다.
- 해킹 액션은 SF 액션으로 시원해야 하지만, 데이터 탈취 / 침투 / 탈출이라는 목표를 잃으면 안 된다.
- 해킹 방어는 단순 뱀서 복붙처럼 보이면 안 된다.
- 바다 / 자유 모티프는 직접적인 새 / 날개 도배가 아니라, 바깥 세계를 동경하는 오브젝트로 표현한다.

## 11. 회의용 이미지에 대한 해석

- 최근 생성한 보드 이미지는 최종 아트가 아니다.
- 메인방, 전력 장비, 해킹 액션, 해킹 방어의 방향성을 논의하기 위한 reference board다.
- 일부 메인방 디자인이나 해킹 액션 디자인은 실제 의도와 어긋난 부분이 있으므로 그대로 구현하지 않는다.
- 실제 구현 판단에서는 이 문서의 텍스트 결정사항을 우선한다.
- 회의용 이미지를 repo에 추가하거나 복사하지 않는다. 필요한 경우 별도 asset 적용 작업에서 경로, 목적, license / source, import metadata를 확인한다.
