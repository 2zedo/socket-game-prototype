# APPLY REFERENCE ASSETS TASK

이번 작업은 레퍼런스를 참고해 비슷하게 만드는 작업이 아니다.

`docs/reference` 폴더에 저장된 맵과 YUI 이미지를 실제 게임 에셋으로 직접 사용한다.

새로운 맵이나 캐릭터를 임의로 만들지 말고, 지정된 파일을 그대로 적용하라.

---

## 1. 반드시 먼저 확인할 파일

저장소 루트의 다음 폴더를 확인한다.

`docs/reference`

이 폴더에는 탐색기에서 다음 이름으로 보이는 이미지가 있다.

- `map`
- `YUI`

Windows 탐색기에서 확장자가 숨겨져 있을 수 있으므로 실제 파일명과 확장자를 직접 확인한다.

작업 전에 반드시 아래 정보를 확인하고 보고한다.

- map 파일의 정확한 파일명
- map 이미지 해상도
- YUI 파일의 정확한 파일명
- YUI 이미지 해상도
- YUI 이미지의 알파 채널 존재 여부
- YUI 이미지가 4열 × 4행, 총 16프레임 구조인지 여부

두 이미지를 실제로 읽을 수 없다면 임의로 대체 에셋을 만들지 말고 작업을 중단한 뒤 문제를 보고한다.

## 2. 이번 작업의 완료 목표

이번 작업에서는 아래 세 가지만 완료한다.

1. `map` 이미지를 실제 게임 방 배경으로 그대로 적용
2. `YUI` 이미지를 실제 플레이어 스프라이트로 적용
3. 기존 이동 및 상호작용 기능이 정상 작동하는지 확인

이번 작업에 UI 재디자인, 신규 기능, 맵 재창작 등은 포함하지 않는다.

---

## 3. 레퍼런스 파일을 Godot 프로젝트 내부로 복사

현재 Godot 프로젝트 루트는 `godot/` 폴더다.

`docs/reference`는 `res://` 외부이므로 원본 파일을 수정하지 말고 Godot 프로젝트 안으로 복사한다.

권장 경로:

- map 원본
  → `godot/assets/art/maps/apartment/apartment_map_reference.png`

- YUI 원본
  → `godot/assets/art/characters/yui/yui_source_sheet.png`

실제 확장자가 PNG가 아니라면 원본 형식을 확인한 뒤 Godot에서 사용할 수 있는 형식으로 복사하거나 변환한다.

`docs/reference`의 원본 파일은 삭제하거나 덮어쓰지 않는다.

## 4. 맵 이미지를 그대로 적용

`apartment_map_reference` 이미지를 현재 방의 배경 이미지로 직접 사용한다.

중요 규칙:

- 이미지와 비슷한 맵을 다시 만들지 않는다.
- Godot의 ColorRect, Polygon2D, 임시 사각형 등으로 가구를 재구성하지 않는다.
- 이미지 한 장을 Sprite2D 또는 적절한 TextureRect로 직접 표시한다.
- 이미지 비율을 찌그러뜨리지 않는다.
- 1280×720 실행 화면에 전체 맵이 자연스럽게 보이도록 동일 비율로 배치한다.
- 임의로 가구 위치, 멀티탭, 전선, 창문, 방 구조를 다시 해석하지 않는다.

현재 씬에서 레퍼런스 이미지 위에 겹쳐 보이는 아래 임시 시각 요소는 제거하거나 숨긴다.

- 기존 임시 바닥
- 기존 임시 벽
- 기존 placeholder 가구
- 기존 사각형 오브젝트 그림
- 이전 작업에서 생성된 임시 맵 장식

단, 기능을 담당하는 노드와 스크립트는 삭제하지 않는다.

유지해야 할 기능:

- 플레이어 이동
- 충돌
- 멀티탭 상호작용
- 노트북 상호작용
- 선풍기 상호작용
- 충전기 상호작용
- 통신장치 상호작용
- 하루 종료
- 전력 및 게임 상태 데이터

기존 상호작용 노드는 투명한 Area2D 또는 기능 노드로 유지하고, 레퍼런스 맵에 보이는 해당 오브젝트 위치로 옮긴다.

평상시에는 충돌 영역과 상호작용 영역이 화면에 보이지 않아야 한다.

## 5. YUI 이미지를 그대로 사용

`YUI` 이미지 속 캐릭터를 실제 플레이어로 사용한다.

절대 금지:

- 비슷한 캐릭터를 새로 그리는 것
- 임시 픽셀 캐릭터로 대체하는 것
- 머리, 의상, 얼굴, 색상을 임의로 바꾸는 것
- 사각형이나 단순 도형 플레이어를 유지하는 것

YUI 이미지는 다음 구조로 사용한다.

- 1행: 아래 방향 걷기 4프레임
- 2행: 왼쪽 방향 걷기 4프레임
- 3행: 오른쪽 방향 걷기 4프레임
- 4행: 위 방향 걷기 4프레임

총 4열 × 4행, 16프레임이다.

애니메이션 이름:

- `walk_down`
- `walk_left`
- `walk_right`
- `walk_up`
- `idle_down`
- `idle_left`
- `idle_right`
- `idle_up`

Idle 애니메이션은 각 방향 행에서 가장 자연스러운 정지 프레임 한 장을 사용한다.

## 6. YUI 배경 투명 처리

YUI 파일의 알파 채널을 먼저 확인한다.

### 실제 투명 배경인 경우

원본을 그대로 프레임 분할한다.

### 흰색과 회색 체커무늬가 이미지에 포함된 경우

체커무늬는 투명 배경 표시가 아니라 이미지에 실제로 들어간 배경이므로 반드시 제거한다.

Python Pillow 등을 이용한 처리 스크립트를 작성한다.

권장 스크립트 경로:

`tools/process_yui_sprite_sheet.py`

처리 원칙:

- 원본 YUI 파일은 수정하지 않는다.
- 밝은 흰색과 회색 체커 배경만 제거한다.
- 검은 머리와 검은 의상을 손상시키지 않는다.
- 피부색과 의상 테두리를 최대한 보존한다.
- 캐릭터 주변에 흰색 또는 회색 테두리가 남지 않게 한다.
- 최종 결과는 실제 알파 채널이 있는 RGBA PNG여야 한다.

결과 파일:

`godot/assets/art/characters/yui/yui_walk_4dir_rgba.png`

## 7. 프레임 정렬

16개 프레임은 모두 동일한 크기의 셀에 들어가야 한다.

각 프레임에서 아래 기준을 동일하게 맞춘다.

- 캐릭터의 전체 높이
- 발바닥 기준선
- 몸의 중심 좌표
- 좌우 여백
- 상하 여백

걷는 동안 캐릭터가 커졌다 작아지거나, 좌우 또는 위아래로 흔들려 보이면 안 된다.

원본의 프레임 위치가 균등하지 않다면 다음 순서로 처리한다.

1. 캐릭터 프레임을 각각 분리
2. 배경을 투명 처리
3. 발 중심을 기준으로 동일 셀에 정렬
4. 4열 × 4행 아틀라스로 다시 합치기

캐릭터 자체를 새로 그리거나 형태를 변형하지 않는다.

## 8. Godot Player에 적용

기존 Player 노드의 임시 시각 요소를 제거하고 YUI 스프라이트를 적용한다.

권장 설정:

- AnimatedSprite2D 사용
- Texture Filter: Nearest
- Mipmap: 비활성화
- 걷기 애니메이션: 약 7~8 FPS
- 픽셀 스냅 또는 정수 배율 우선
- 선형 보간으로 흐릿하게 만들지 않기

1280×720 기준 캐릭터 표시 높이는 약 48~56px 범위에서 시작한다.

캐릭터가 너무 작아 점처럼 보이거나, 가구보다 지나치게 크게 보이지 않게 조정한다.

충돌 영역은 캐릭터 전신이 아니라 발 주변에 작게 배치한다.

기존 프로젝트가 Y-sort 또는 다른 깊이 정렬 방식을 사용하고 있다면 그 구조를 유지한다.

## 10. 실행 테스트

Godot 프로젝트를 실행해 다음 항목을 확인한다.

- 레퍼런스 map 이미지가 그대로 배경에 표시되는가
- 이미지 비율이 찌그러지지 않았는가
- 기존 임시 맵이나 사각형 가구가 겹쳐 보이지 않는가

- YUI 주변에 체커무늬 또는 흰 배경이 보이지 않는가
- 상하좌우 걷기 방향이 정확한가
- 걷는 동안 캐릭터 크기와 위치가 심하게 흔들리지 않는가
- 플레이어 이동이 정상 작동하는가
- 기존 상호작용 기능이 정상 작동하는가

가능하면 실행 화면을 다음 경로에 저장한다.

## 12. Git commit과 push

실행 테스트가 성공한 경우에만 Git 작업을 수행한다.

순서:

1. `git status`
2. 변경 파일 확인
3. 필요한 파일만 `git add`
4. `.godot/`와 임시 캐시 제외
5. commit
6. push

커밋 메시지:

`feat: apply reference apartment map and YUI sprite assets`

Push:

`git push origin main`

`git add .`로 모든 파일을 무조건 추가하지 않는다.

테스트가 실패했거나 캐릭터 배경 제거 또는 프레임 정렬에 문제가 있다면 완료로 기록하거나 push하지 않는다.

문제 원인과 미완료 항목을 정확히 보고한다.
